# MarkOrbit Work DAG V1

`MARKORBIT_WORK_DAG_V1`

Work DAG V1 makes execution dependencies explicit before Data Engine replaces mature legacy publishers with native platform tasks.

## Why this exists

The CN M1.6 final publisher is semantically correct and now bounded/resumable, but its workflow is still encoded partly by Python call order and SQL-shape interception. That is safe as a compatibility layer, but it is not the architecture to copy to WIPO, EUIPO, JPO, or future jurisdictions.

M1.7 therefore separates two concepts:

```text
semantic DAG = authority
legacy SQL matching = temporary compatibility bridge
```

The DAG defines task identity, operation kind, output target, partition strategy, dependencies, and audit policy. A compatibility rule may identify which existing SQL command currently implements a node, but that rule is not the semantic definition of the node.

## CN Final Publish DAG V1

`CN_FINAL_PUBLISH_DAG_V1` explicitly models the current final publisher from source-fact change events through Current publication, auxiliary snapshots, derived-case relations, and scope carve-outs.

The first foundation release intentionally reports:

```text
native_node_count = 0
execution_mode = LEGACY_PUBLISHER_MAPPED_TO_EXPLICIT_DAG
```

That is deliberate. The first milestone freezes and tests the existing semantics without changing SQL hashes, source-rank behavior, checkpoint keys, or Storage V2 behavior.

## Migration rule

Native execution is enabled **per node**, never by replacing the whole publisher in one cutover.

For each node:

1. preserve the DAG task identity and dependencies;
2. implement native SQL/build logic without regex interception;
3. reuse Generic Work Engine partition/checkpoint semantics where the node is large;
4. prove semantic equivalence against the compatibility implementation with real PostgreSQL/ClickHouse fixtures;
5. mark only that node `native_execution=true`;
6. keep downstream acceptance/audit gates unchanged.

This allows CASE_CURRENT, CASE_SCOPE_CURRENT, CASE_PARTY_CURRENT, events, auxiliary snapshots, and relation tasks to migrate independently.

## Fail-closed compatibility

CI captures the SQL commands generated by the real CN M1.6 legacy publisher after its M1.6 aggregate/event substitutions. Every source-backed publish command must resolve to exactly one DAG node and the observed order must satisfy the dependency graph.

Unknown, ambiguous, or mixed source shapes fail the contract test. This turns future legacy drift into an explicit migration decision rather than a hidden production behavior change.

## Permanent semantic boundary

A Work DAG schedules source-fact computation. It does not authorize legal conclusions, business workflow, client communication, filing actions, or Matter state. Those remain outside Data Engine.
